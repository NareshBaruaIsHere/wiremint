# Security Policy

The Wiremint project takes security seriously. We appreciate the responsible disclosure of security vulnerabilities by developers, researchers, and users.

---

## Supported Versions

Only the latest active minor release is officially supported with security updates.

| Version | Supported          |
| ------- | ------------------ |
| 0.1.x   | :white_check_mark: |
| < 0.1.0 | :x:                |

---

## Reporting a Vulnerability

If you discover a potential security vulnerability in Wiremint, **please do not disclose it publicly** through public GitHub issues, discussions, or social media.

Instead, report it privately through:

1. **GitHub Private Security Advisory**:  
   Submit a confidential advisory directly via the repository's [Security Advisory dashboard](https://github.com/NareshBaruaIsHere/wiremint/security/advisories/new).

2. **Private Email**:  
   If you are unable to use GitHub Security Advisories, contact the repository maintainer directly at the contact address listed on the maintainer's GitHub profile (`NareshBaruaIsHere`).

### What to Include in Your Report

To help us investigate and triage the issue quickly, please provide:
- A clear description of the vulnerability and its potential impact.
- Affected component(s) (e.g., Local Control Plane, Request Inspector redaction, HTTP server).
- Step-by-step reproduction instructions or a minimal proof of concept script.
- Any proposed remediations or patches if available.

---

## Response Process

- **Acknowledgment**: We aim to acknowledge reports within 48 hours.
- **Assessment**: We will verify the vulnerability and assess its severity.
- **Fix & Disclosure**: We will prepare a fix, draft a security advisory, and release a patched version.
